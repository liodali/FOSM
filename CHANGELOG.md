## Unreleased

* Draw missing-tile placeholders in the grid painter as one pre-rasterized image instead of replaying the checkerboard picture (`RenderCanvasOSM.placeholderImage`, on by default; `--dart-define=fosm.gridPlaceholderImage=false` reverts per build). Profiling on an iPhone 12 mini showed 95 % of the grid repaint was the replay (about 150 µs per tile against 6 µs for an image draw). Clean paired A/B over Wi-Fi (warm scenarios; replay vs image, two to three runs per arm): pinch UI p99 8.86 / 8.86 → 3.76 / 3.70 / 3.64 ms and fling 4.54 / 6.25 → 2.83 / 2.62 / 2.76 ms, raster and stale area unchanged, zero frames over 16.7 ms in every run. Cold gestures (two runs per arm): pinch UI p99 9.5–9.8 → 3.3–4.1 ms, fling 3.9–5.2 → 2.7 ms; time to all-sharp is unchanged (pacing-bound). Android (vivo V2542, Snapdragon SM8845, one run per arm): pinch UI p99 8.1 → 3.8 ms warm and 8.8 → 4.3 ms cold, cold fling 5.6 → 2.9 ms; warm fling shows no gain in one run. The image is sampled with nearest filtering, so placeholder cell edges differ from the replay by at most 14/255 per channel at fractional offsets (identical at integer offsets and scale 1).

* Ship the vector zoom-softness fix as payload-scoped defaults: vector maps render tiles at **512 px** (was 256; `fosm.vectorTileResolution` override, mutable `VectorTileRuntime.resolution`) and resolve the rendered-image budget to **150 MB** when `maxRenderedCacheBytes` is left unset (`MapView.vectorRenderedCacheDefaultBytes`, inside the accepted 100–200 MB band; an explicit value still wins). Raster payloads are untouched: 50 MB rendered budget and the historical natural-size draw path, pixel-for-pixel (locked by painter-level and end-to-end pixel tests). Basis: the macOS/Impeller resolution A/B (docs/performance/vector-render-improvement/zoom-softness-diagnostic.md) — 2.3× edge energy at the max-enlargement fractional pose, zero over-budget frames during pinch/wheel with the scaled budget (the 50 MB default thrashed: sharp coverage 1.0 → 0.73, raster p95 → 17 ms), tile-production cost confined to the background `toImage` lane (p95 28 → 53 ms, median unchanged), RSS flat. On web (CanvasKit/SkWasm) the 512 px `toImage` is heavier — the define reverts per build if a web regression shows up.

* Add the vector zoom-softness diagnostic (`test/view/vector_zoom_softness_diagnostic_test.dart`, findings in `docs/performance/vector-render-improvement/zoom-softness-diagnostic.md`): the same 13.8 → 14.4 fractional trajectory through real pinch (held mid-gesture) and mouse-wheel gestures, with the prepared zoom window at its shipped default, comparing sharpness (Laplacian variance of the zoomed-pose capture vs the zoomScale-1.0 reference, PNG dumps in `build/vector_zoom_diag/`) against grid-paint frame cost (`RenderCanvasOSM.debugPaintCount`, `paint.grid` span percentiles, `debugGridRecaptures`). Verdict: bypassing retained scaling for vector payloads (`--dart-define=fosm.vectorRetainedScale=false`, raster payloads unchanged) does not improve sharpness — both paths resample the same 256 px tile bitmaps once at the live scale — while it costs one grid repaint (~600 µs record CPU) per driven frame; the diagnostic asserts the switch behavior and keeps the arm for a device-side raster-cache verdict. Tile-image resolution is the dominant lever: `--dart-define=fosm.vectorTileResolution=512` (default 256; mutable `VectorTileRuntime.resolution` for harnesses) nearly doubles zoomed-pose sharpness (×0.270 → ×0.523 of reference) at 4× imagery memory and zero extra paints, with `RenderCanvasOSM` mapping higher-resolution captures onto the tile rect (preview/fallback paths already resolution-agnostic; the flag is part of the painter's `shouldRepaint` contract with a flip-at-equal-fields regression test).
